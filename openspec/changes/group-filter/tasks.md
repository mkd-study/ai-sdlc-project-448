# Tasks

Реализацию выполнять скиллом `tdd` на Node.js 26: каждый поведенческий срез начинать с падающего теста, затем добавлять минимальную реализацию и рефакторить при зелёных тестах. Контракт поведения — [employee-selection](specs/employee-selection/spec.md), технические решения — [design.md](design.md).

## 1. Общие правила выбора сотрудника

- [ ] 1.1 Добавить через TDD чистую функцию фильтрации и согласования выбора в `src/app/employee-selection.ts` и экспорт через `src/app/index.ts`. В соседних тестах проверить полный список, одну и несколько групп, повтор связи, исходный порядок, сотрудника без групп, пустые списки, отсутствующую группу и сохранение либо сброс сотрудника; проверить неизменность входной конфигурации. Подтверждение: `npm test -- src/app/employee-selection.test.ts` и `npm run typecheck` проходят.

## 2. Фильтр при проверке доступа

- [ ] 2.1 Добавить в `App.tsx` независимое состояние группы и поле «Группа сотрудников для проверки» с вариантом «Все группы», используя общий модуль. Через TDD в `App.test.tsx` проверить начальный полный список, выбор группы и сотрудника, несколько групп, сотрудника без групп, отсутствие групп и пустую группу с сообщением. Подтверждение: `npm test -- src/components/App.test.tsx` проходит.
- [ ] 2.2 Реализовать согласование сотрудника при смене фильтра с сохранением сервиса. Сначала добавить тесты сохранения видимого сотрудника, сброса скрытого, отсутствия автоматического выбора и самовосстановления, очистки результата и источников. Проверить через интерфейс полный расчёт с прямым разрешением и двумя группами, а также отсутствие доступа. Подтверждение: `npm test -- src/components/App.test.tsx` проходит вместе с прежними сценариями.

## 3. Фильтр при выдаче разрешений

- [ ] 3.1 Добавить в `PermissionsPanel.tsx` поле «Группа сотрудников для выдачи» с независимым состоянием. Фильтровать только сотрудников, оставив всех групповых получателей и полный список разрешений. Через TDD в `Permissions.test.tsx` проверить состав вариантов, пустую группу, сохранение группы-получателя и независимость двух фильтров в обоих направлениях. Подтверждение: `npm test -- src/components/Permissions.test.tsx` проходит.
- [ ] 3.2 Согласовать выбранного сотрудника и доступность выдачи при смене фильтра. Через TDD проверить сброс скрытого получателя без восстановления, сохранение сервиса и видимого получателя, выдачу отфильтрованному сотруднику, защиту от дубля и выдачу группе, отличной от группы фильтра. Подтверждение: соответствующие сценарии `Permissions.test.tsx` проходят, выдача изменяет только требуемое разрешение.

## 4. Импорт и сохранность текущих возможностей

- [ ] 4.1 Согласовать значения обеих форм с успешным импортом. Через TDD и загрузку файла проверить удаление группы фильтра с возвратом «Все группы», сохранение допустимого выбора, изменение членства при тех же идентификаторах, удаление сотрудника, группы-получателя и сервиса, пустую конфигурацию и отсутствие восстановления удалённого выбора при следующем импорте. Подтверждение: `npm test -- src/components/App.test.tsx src/components/Permissions.test.tsx` проходит; расчёт и выдача используют только допустимые значения.
- [ ] 4.2 Добавить поведенческие проверки ошибочного импорта при двух активных фильтрах, неизменности экспорта и хранилища после фильтрации, сохранения всех разрешений в списке, удаления только одного источника и перезагрузки с сохранёнными разрешениями и фильтрами «Все группы». Исправления по выявленным расхождениям выполнять через TDD. Подтверждение: `npm test -- src/components/Permissions.test.tsx` проходит с прежними и новыми сценариями.

## 5. Интеграционная проверка

- [ ] 5.1 На Node.js 26 выполнить `make build && make test && make lint && make lint-arch`; все команды должны завершиться успешно. Вручную сверить зависимости с `docs/architecture.md` и требованиями `docs/security-requirements.md`, поскольку текущие правила ast-grep не проверяют границы модулей; подтвердить отсутствие изменений `.github/workflows/hexlet-check.yml`.
- [ ] 5.2 Проверить в браузере обе формы с клавиатуры: различимые подписи, выбор группы и сотрудника, возврат полного списка, пустую группу и выдачу группового разрешения. Подготовить скриншоты обеих форм с активными фильтрами для будущего запроса на слияние; результат проверки — доступные поля без наложений, работоспособные сценарии и сохранённые изображения.
