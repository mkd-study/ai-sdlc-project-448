# Tasks

Реализацию выполнять скиллом `tdd` на Node.js 26: каждый поведенческий срез начинать с падающего теста, затем добавлять минимальную реализацию; рефакторинг относится к этапу ревью. Контракт поведения — [employee-selection](specs/employee-selection/spec.md), технические решения — [design.md](design.md). Согласованные границы тестирования сохраняются: публичная функция `selectEmployees` через `src/app/index.ts` и приложение через пользовательские действия.

Коммит `57c6eea` реализует предыдущую редакцию. Задачи 1–2 сохраняют выполненный статус; задачи 3–5 выполнены для уточнённой формы выдачи с повторными проверками. Результаты новой редакции приведены ниже.

## 1. Общие правила выбора сотрудника

- [x] 1.1 Добавить через TDD чистую функцию фильтрации и согласования выбора в `src/app/employee-selection.ts` и экспорт через `src/app/index.ts`. В соседних тестах проверить полный список, одну и несколько групп, повтор связи, исходный порядок, сотрудника без групп, пустые списки, отсутствующую группу и сохранение либо сброс сотрудника; проверить неизменность входной конфигурации. Подтверждение: `npm test -- src/app/employee-selection.test.ts` и `npm run typecheck` проходят.

## 2. Фильтр при проверке доступа

- [x] 2.1 Добавить в `App.tsx` независимое состояние группы и поле «Группа сотрудников для проверки» с вариантом «Все группы», используя общий модуль. Через TDD в `App.test.tsx` проверить начальный полный список, выбор группы и сотрудника, несколько групп, сотрудника без групп, отсутствие групп и пустую группу с сообщением. Подтверждение: `npm test -- src/components/App.test.tsx` проходит.
- [x] 2.2 Реализовать согласование сотрудника при смене фильтра с сохранением сервиса. Сначала добавить тесты сохранения видимого сотрудника, сброса скрытого, отсутствия автоматического выбора и самовосстановления, очистки результата и источников. Проверить через интерфейс полный расчёт с прямым разрешением и двумя группами, а также отсутствие доступа. Подтверждение: `npm test -- src/components/App.test.tsx` проходит вместе с прежними сценариями.

## 3. Связанный выбор группы и получателя

- [x] 3.1 Обновить `PermissionsPanel.tsx`: начальная группа «Не выбрана»; в «Кому выдать» пустой вариант, «Все сотрудники группы» только при выбранной группе и доступные сотрудники. Удалить повторный перечень групп, сохранить полный список разрешений и независимость от проверки доступа. Через TDD в `Permissions.test.tsx` заменить прежние ожидания и проверить варианты без группы, с группой, с пустой группой, сотрудников без групп и отсутствие автоматического выбора получателя. Подтверждение: `npm test -- src/components/Permissions.test.tsx` проходит; при пустой группе общий вариант доступен, без группы отсутствует.
- [x] 3.2 Связать «Все сотрудники группы» с одним разрешением выбранной группе; при смене или снятии группы сбрасывать этот выбор, при сохранении той же группы оставлять его. Через TDD проверить сохранение сервиса, сброс без восстановления, недоступность выдачи без получателя, одно групповое разрешение без прямых разрешений участникам, защиту от дубля и прямую выдачу конкретному сотруднику. Сохранить выбор видимого сотрудника и сбрасывать скрытого. Подтверждение: `npm test -- src/components/Permissions.test.tsx` проходит, операция изменяет только выбранное разрешение.

## 4. Импорт и сохранность текущих возможностей

- [x] 4.1 Согласовать получателя с импортом в новой форме выдачи. Через TDD и загрузку файла проверить сброс «всех» при удалении выбранной группы с переходом к «Не выбрана», сохранение выбора всех при изменении состава той же группы, в том числе до пустого, и доступ нового участника через ранее выданное групповое разрешение. Сохранить проверки сброса скрытого сотрудника, удалённого сервиса, пустой конфигурации, отсутствия самовосстановления и неизменного поведения проверки доступа. Подтверждение: `npm test -- src/components/App.test.tsx src/components/Permissions.test.tsx` проходит, получатель всегда согласован с текущими данными.
- [x] 4.2 Адаптировать проверки сохранности операций к новому выбору получателя: ошибочный импорт сохраняет выбор группы и всех её участников либо конкретного сотрудника; фильтрация не меняет экспорт, хранилище и список разрешений; удаление одного источника сохраняет независимые. Проверить перезагрузку с сохранёнными разрешениями, «Все группы» при проверке доступа и «Не выбрана» при выдаче без общего варианта. Подтверждение: `npm test -- src/components/Permissions.test.tsx` проходит с актуальными сценариями; исправления при необходимости выполнять через TDD.
