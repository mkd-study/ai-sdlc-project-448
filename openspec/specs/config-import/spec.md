# Импорт конфигурации

## Purpose

Зафиксировать текущее поведение разбора, проверки и загрузки конфигурации из `src/app/config-file.ts` и `src/app/storage.ts`, опираясь на соседние тесты. Применение результата импорта дополнительно описано по `src/app/index.ts` и проверкам в `src/components/Permissions.test.tsx`.

`parseConfigFile(text)` возвращает либо `{ ok: true, config }`, либо `{ ok: false, errors: string[] }`. `loadConfig(storage)` возвращает проверенную конфигурацию или учебные данные. Спецификация описывает существующие ограничения, включая фактически принимаемые значения версии; интерфейс выбора файла и расчёт доступа находятся вне её области.

Обязательные поля записей формата:

| Список | Поля записи |
| --- | --- |
| `users` | Непустые строки `id`, `name`; массив непустых строк `groupIds` |
| `groups`, `services` | Непустые строки `id`, `name` |
| `permissions` | Непустые строки `id`, `serviceId`; объект `subject` с `type: "user"` или `"group"` и непустой строкой `id` |

## Requirements

### Requirement: Разбор JSON и корневого объекта

Парсер SHALL принимать текст JSON с корневым объектом, отличным от `null` и массива. При ошибке разбора или неверном корне он SHALL возвращать отказ с единственной соответствующей ошибкой, без дальнейшей проверки.

#### Scenario: Повреждённый JSON

- **WHEN** передан текст `{oops`
- **THEN** результат равен `{ ok: false, errors: ["Файл не разбирается как JSON"] }`

#### Scenario: Корень не является объектом конфигурации

- **WHEN** передан JSON `[]`, `null`, строка, число или логическое значение
- **THEN** результат равен `{ ok: false, errors: ["Файл должен содержать объект конфигурации"] }`

### Requirement: Проверка версии формата

Парсер SHALL требовать числовое целое поле `version` и отвергать значения больше `CONFIG_VERSION`, равного `1`. Текущая реализация SHALL принимать любую целую версию не больше `1`, включая `0` и отрицательные значения, при соблюдении остальных требований к данным. Отдельные миграции формата не выполняются.

#### Scenario: Версия отсутствует или имеет неверный тип

- **WHEN** поле `version` отсутствует, равно строке `"1"`, `null` или дробному числу `1.5`
- **THEN** возвращается только ошибка `Нет поля version с целым числом`

#### Scenario: Версия новее поддерживаемой

- **WHEN** поле `version` равно `2`
- **THEN** возвращается только ошибка `Версия формата 2 новее поддерживаемой 1`

#### Scenario: Нижняя граница версии не проверяется

- **GIVEN** файл удовлетворяет требованиям к структуре и ссылкам
- **WHEN** поле `version` равно `0` или `-1`
- **THEN** файл принимается и возвращается конфигурация без поля `version`

### Requirement: Обязательные списки и структура записей

Парсер SHALL требовать массивы `users`, `groups`, `services` и `permissions`, допуская пустые массивы. Каждый элемент SHALL быть объектом, отличным от `null` и массива, с обязательными полями из таблицы формата выше. Проверка строк SHALL проверять тип и отличие от `""` без удаления пробелов. Парсер SHALL сохранять порядок записей и содержимое допустимых строк.

#### Scenario: Пустая конфигурация

- **WHEN** передан объект с `version: 1` и четырьмя пустыми массивами
- **THEN** возвращается `{ ok: true, config: { users: [], groups: [], services: [], permissions: [] } }`

#### Scenario: Отсутствующий список

- **GIVEN** остальные поля корректны
- **WHEN** поле `groups` отсутствует или не является массивом
- **THEN** файл отвергается с ошибкой `Поле groups должно быть списком`

#### Scenario: Неверная запись или обязательное поле

- **GIVEN** остальные поля корректны
- **WHEN** `users[1]` равен `null`
- **THEN** возвращается ошибка `users[1]: запись должна быть объектом`
- **AND** если вместо этого у корректного объекта `users[1]` поле `name` равно `5` или `""`, возвращается ошибка `users[1]: поле name должно быть непустой строкой`

#### Scenario: Неверные группы пользователя

- **WHEN** `users[0].groupIds` отсутствует, не является массивом или содержит число либо пустую строку
- **THEN** файл отвергается с ошибкой `users[0]: поле groupIds должно быть списком строк`

#### Scenario: Неверный субъект разрешения

- **WHEN** `permissions[0].subject` отсутствует, равен `null` или массиву
- **THEN** возвращается ошибка `permissions[0]: поле subject должно быть объектом`
- **AND** если субъект является объектом с `type: "team"`, возвращается ошибка `permissions[0]: тип субъекта должен быть user или group`

#### Scenario: Пробелы в строках

- **GIVEN** остальные поля и ссылки корректны
- **WHEN** имя пользователя равно `" "`
- **THEN** файл принимается, а имя сохраняется без изменений

### Requirement: Уникальность идентификаторов внутри списка

Парсер SHALL отвергать повторение `id` среди корректно разобранных записей одного списка. Одинаковые идентификаторы в разных списках допускаются. Проверка SHALL ограничиваться идентификаторами записей: повторные значения в `groupIds` и разрешения на один субъект и сервис с разными `id` принимаются, если ссылки корректны.

#### Scenario: Повтор идентификатора сервиса

- **GIVEN** первый сервис имеет `id: "ledger"`
- **WHEN** второй корректный сервис также имеет `id: "ledger"`
- **THEN** файл отвергается с ошибкой `services[1]: идентификатор «ledger» уже занят`

#### Scenario: Повторные разрешения с разными идентификаторами

- **GIVEN** два разрешения с разными `id` ссылаются на одного существующего пользователя и один существующий сервис
- **WHEN** файл разбирается
- **THEN** оба разрешения сохраняются в принятой конфигурации

### Requirement: Проверка ссылочной целостности

После успешной проверки структуры парсер SHALL проверять все ссылки: каждый `groupIds` пользователя указывает на существующую группу; `subject.id` разрешения указывает на пользователя или группу согласно `subject.type`; `serviceId` указывает на существующий сервис. Любая отсутствующая ссылка SHALL приводить к отказу с индексом записи в исходном массиве.

#### Scenario: Пользователь ссылается на отсутствующую группу

- **WHEN** `users[0].groupIds` содержит `ghosts`, отсутствующую в `groups`
- **THEN** возвращается ошибка `users[0]: нет группы «ghosts»`

#### Scenario: Разрешение ссылается на отсутствующего субъекта

- **WHEN** `permissions[0]` ссылается на пользователя `nobody`, отсутствующего в `users`
- **THEN** возвращается ошибка `permissions[0]: нет пользователя «nobody»`
- **AND** для ссылки разрешения группы на отсутствующую группу `ghosts` возвращается ошибка `permissions[0]: нет группы «ghosts»`

#### Scenario: Разрешение ссылается на отсутствующий сервис

- **WHEN** `permissions[2].serviceId` равен `vault`, отсутствующему в `services`
- **THEN** возвращается ошибка `permissions[2]: нет сервиса «vault»`

### Requirement: Поэтапное накопление ошибок без частичного результата

Парсер SHALL возвращать конфигурацию только после успешного завершения всех проверок. После проверки JSON, корня и версии он SHALL обходить все четыре списка и накапливать найденные ошибки структуры и дубликатов. При наличии таких ошибок проверка ссылок не выполняется. При корректной структуре SHALL накапливаться все ошибки ссылок. Ошибочный результат SHALL содержать `ok: false` и `errors`, без частично разобранной конфигурации; сам парсер не изменяет состояние приложения и хранилище.

#### Scenario: Несколько ошибок ссылок

- **GIVEN** структура файла корректна
- **WHEN** `permissions[0].serviceId` равен отсутствующему `vault`, а `permissions[1]` ссылается на отсутствующую группу `ghosts`
- **THEN** возвращается отказ с обеими ошибками и без поля `config`

#### Scenario: Структурная ошибка предотвращает проверку ссылок

- **GIVEN** у `users[0]` неверный тип `name`, а структурно корректное разрешение ссылается на отсутствующий сервис
- **WHEN** файл разбирается
- **THEN** возвращается ошибка поля `name`, а ошибка ссылки на сервис на этом этапе не возвращается

### Requirement: Единый формат и отбрасывание неизвестных полей

Парсер SHALL игнорировать неизвестные поля корня и вложенных записей, возвращая только поля модели `Config`. `exportConfig` SHALL сериализовать конфигурацию модели с `version: 1` и отступами в два пробела; корректная конфигурация SHALL сохраняться по содержимому после экспорта и повторного разбора. Экспорт сам по себе не проверяет структуру и ссылки.

#### Scenario: Неизвестные поля

- **GIVEN** корректному файлу добавлены поле `exportedBy` в корне и `nickname` у пользователя
- **WHEN** файл разбирается
- **THEN** конфигурация принимается без этих полей и без `version`

#### Scenario: Экспорт и повторный импорт

- **GIVEN** корректная конфигурация модели
- **WHEN** вызывается `parseConfigFile(exportConfig(config))`
- **THEN** возвращается `{ ok: true, config }` с теми же данными и порядком записей

### Requirement: Применение проверенного импорта целиком

Операция `importJson` SHALL сначала вызвать парсер. При отказе она SHALL вернуть ошибки и сохранить прежнее состояние и содержимое хранилища. При успехе она SHALL заменить всю конфигурацию, вызвать её сохранение и вернуть `{ ok: true }`. Данные файла не объединяются с прежними; успешный разбор не гарантирует успешную запись в недоступное хранилище.

#### Scenario: Успешная замена конфигурации

- **GIVEN** текущая конфигурация содержит несколько разрешений, а корректный импортируемый файл содержит только одно
- **WHEN** выполняется импорт и хранилище доступно для записи
- **THEN** состояние и сохранённая конфигурация содержат только данные импортированного файла

#### Scenario: Ошибочный импорт сохраняет предыдущие данные

- **GIVEN** в приложении есть текущая конфигурация и сохранённое значение
- **WHEN** импортируемый файл содержит разрешение на отсутствующий сервис
- **THEN** операция возвращает ошибки, а текущая конфигурация и сохранённое значение остаются прежними

### Requirement: Загрузка сохранённой конфигурации и возврат учебных данных

`loadConfig` SHALL читать ключ `access-policy-simulator:config` из переданного `Storage` и проверять полученный текст через `parseConfigFile`. При успехе SHALL возвращаться разобранная конфигурация. При отсутствии значения, ошибке проверки или исключении при чтении SHALL возвращаться `seedConfig`. Загрузка SHALL оставлять содержимое хранилища без изменений, в том числе при возврате учебных данных.

#### Scenario: Корректная сохранённая конфигурация

- **GIVEN** по ключу приложения сохранён корректный JSON
- **WHEN** вызывается `loadConfig(storage)`
- **THEN** возвращается конфигурация из этого JSON

#### Scenario: Нет пригодных сохранённых данных

- **WHEN** ключ отсутствует либо содержит повреждённый JSON, неподдерживаемую версию или некорректные ссылки
- **THEN** возвращается `seedConfig`, а хранилище не очищается и не перезаписывается

#### Scenario: Чтение хранилища завершается исключением

- **WHEN** `storage.getItem` выбрасывает исключение
- **THEN** `loadConfig` возвращает `seedConfig` и не передаёт исключение вызывающему коду

### Requirement: Сохранение в формате экспорта и обработка ошибок записи

`saveConfig` SHALL записывать результат `exportConfig(config)` по ключу `access-policy-simulator:config`. Функция не выполняет дополнительную проверку конфигурации. При исключении во время сериализации или записи она SHALL завершаться без передачи исключения вызывающему коду и без отдельного результата об ошибке.

#### Scenario: Сохранённый текст совпадает с экспортом

- **WHEN** вызывается `saveConfig(storage, config)` с корректной конфигурацией и доступным хранилищем
- **THEN** значение ключа приложения равно `exportConfig(config)`

#### Scenario: Ошибка записи

- **WHEN** `storage.setItem` выбрасывает исключение, например из-за исчерпания квоты
- **THEN** `saveConfig` завершается без исключения; сохранение данных между перезагрузками не гарантируется
